        spec returns `("", ErrMetadataUnresolved)` so callers can
        distinguish "nothing configured" from "stat failed".
      - The candidate silently re-reads
        `TOVARISCH_CANARY_METADATA_PATH` when both `cliFlag` and
        `envValue` are empty. CORRECTION48 requires the environment to
        be read once at call time and the CLI flag to be honored on its
        own — no candidate-side re-resolution.

        nonexistent paths and returns the absolute path instead,
        deferring failure to the caller's `os.Stat`. CORRECTION48
        treats a missing path on a configured source as an error at
        resolution time, not at stat time.
      - `os.Stat` happens after `filepath.EvalSymlinks`; CORRECTION48
        evaluates via a single Lstat-then-EvalSymlinks walk that
        rejects sockets/devices/FIFOs as a class.
      - No `validate-via-Read` step: the candidate resolves the path
        but never verifies the JSON parses or that schema/identity
        survive validation. CORRECTION48 requires the resolver to
        call `buildmetadata.Read` and return the canonical path only
        after the metadata validates.
  - Resolution order (CLI flag > env > legacy) is preserved.
  - Do NOT copy this file. Reimplement it deliberately at the
    intended production path with the corrected signature,
    EnvVariableConstant, validation, and non-regular-file rejection.
